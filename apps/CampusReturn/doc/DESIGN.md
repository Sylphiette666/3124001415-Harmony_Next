# 归物设计与接口

## 模块和数据流

`Index.ets` 负责广场、发布、认领、我的、管理与详情面板。`Camera.ets` 管理 CameraKit 生命周期；`CampusAI` 调用 CoreVisionKit、NaturalLanguageKit 并在必要时运行端侧 YOLO；`VoiceService` 处理授权、16kHz PCM 和 CoreSpeechKit。所有抽取结果回填可编辑表单，未确认不发布。

`CacheStore` 将连接设置、物品快照、增量游标和待传任务写入 S2 RDB。`CampusSync` 上传已持久化任务并分页拉取变化，`ApiClient` 管理 JWT 和一次401刷新。后端 `engine.py` 是纯评分与校验规则，`service.py` 实施状态机，`database.py` 使用 SQLite WAL 与 `BEGIN IMMEDIATE` 串行写事务，`app.py` 提供 FastAPI DTO、鉴权及角色校验。

## 采集能力与降级

本机 API24 CoreVisionKit 导出 `objectDetection`，没有名为 `imageClassification` 的导出。本工程调用 `ObjectDetector.process(Request)` 的通用分类标签，22映射卡片、21映射文档；其余校园类别由真实 YOLOv13-N 检测补充。类别建议仍须用户确认，通用文档标签可能无法区分书本与证件。OCR 使用 `textRecognition.recognizeText`；实体抽取调用 `textProcessing.init/getWordSegment/getEntity` 的 LOCATION、DATETIME，类别颜色另用校园词表。系统能力不可用时，页面明确标注实际失败及本地规则，允许重试和手动填写。

图像各阶段各自拥有 PixelMap，原生任务结束后再释放；12秒超时只控制页面等待，不提前销毁仍在使用的资源。上传图片长边压缩至1000、JPEG质量85，超过1.5MB拒绝。相册 URI 复制到私有目录，拍照返回 `campusCapture` 后进入发布页。

## 评分公式

首先校验类别相同、失物时间≤拾获时间、间隔≤168小时。通过后：

`score = 0.30×place + 0.20×time + 0.25×OCR + 0.20×description + 0.05×color`

地点同名或别名为1、包含关系0.8、相邻食堂0.5、同组教学楼0.65、无关为0；时间因子是 `max(0,1-gap/window)`。OCR和描述均经 jieba 分词、规范化和停用词过滤后计算集合 Jaccard（空集合为0）。同色为1，否则0。自动阈值默认0.62；权重和必须为1。

管理员可提交完整策略配置五个权重、阈值、时间窗、超时、发布信用门槛、封禁次数及信用奖惩。UI提供三组权重预设和阈值。新候选实时评分，已有匹配保留历史分数。对于已锁定的待确认匹配，新高分候选不自动替换，返回 `MATCH_LOCKED`；用户仍可通过竞领申请加入队列。这样不会悄悄撤销已经通知的匹配。

## 状态机和队列

登记初始待匹配；自动或手动建对进入已匹配待确认。申请写入认领申请中事件，再进入排队或凭证核验中。有两名以上有效申请时，匹配状态显示竞领中；申请行单独标记排队、核验中、已通过、已关闭、已完成。SQLite局部唯一索引保证每个招领最多一个“核验中”申请。

L1标准答案服务端仅存 HMAC，规范化后比较，通过为100分，失败即关闭并释放下一人。L2/L3先验证编号是否与受保护OCR线索相交；L3另须可解码图片。高等级材料必须由招领发布者或管理员审核，通过分数为60～100。系统不声称能判断图片或证件真伪，L3的图片、OCR文字仍须审核者人工核对。

所有排队和核验结束后才可确认领取。对已通过申请按 `0.8×凭证分 + 0.2×当前信用分` 降序选择，时间和ID作稳定平局规则；落选者自动收到通知。完成同步关闭同一失物关联的其它流程，防止一份失物登记在两件招领上重复完成。重复完成、未核验完成、申诉锁定时完成均409。

超时在每个业务请求事务开始时懒检查：匹配默认48小时关闭，参与但未完成者按爽约扣分；申诉默认48小时未裁定按不成立关闭。无请求时数据库可暂保留旧状态，下一次请求即时结算；未采用后台常驻任务。

## 申诉和信用

只有完成后的第三方失主可申诉，须关联自己的同类别有效时间窗失物，提交高于原赢家凭证等级的材料。L1问答记录、L2物品编号文字或照片、L3证件图和OCR。等级不足直接驳回；受理锁定原匹配、失物和招领为申诉中。

发布者或管理员裁定成立：关闭原领取、重开原失物和招领，向申诉人优先推送通知；已有申诉人匹配可重开并优先排队。原认领者扣40分并累计冒领次数。不成立维持原结果，申诉者扣20分。超时也维持原结果，但不把平台延迟当作已证实恶意而扣申诉人信用。全部操作写入时间线，相关用户收到通知。

初始100分，上限150；完成+5、爽约−10、虚假发布−15、冒领−40、恶意申诉−20。奖惩以用户＋类型＋业务原因唯一去重。默认低于60分拦截新发布，冒领两次禁止认领；客户端不能提交信用或角色来改变判定。人工违规入口仅处理爽约与虚假发布，冒领及恶意申诉由裁定产生。

## 本地缓存和重试

缓存、待传队列、游标均以服务地址＋账号隔离。发布先在同一事务写队列和本地“待上传”卡片；失败记录错误、尝试次数和重试时间，2秒起指数退避至最多5分钟。每条发布生成一次 UUID，重试不改变 payload 或 itemId。服务端按所有者及内容摘要幂等：相同重传返回 duplicate，ID冲突409。客户端只在ACK的ID和状态均合法时删除队列。

同步单次两条变化，避免图片导致大响应；每页内容与游标同事务落盘。游标用独立changes序列而非物品更新时间，分页不会跳过相同时间的变动。应用可见时每15秒与网络恢复事件触发重试，进入后台停止；重启继续持久化任务。账号切换被同步互斥锁拦截，避免迟到回包污染另一账号。App设置和口令位于应用私有S2数据库，远程服务配置只接受HTTPS。

## 接口与权限

| 接口 | 功能和约束 |
|---|---|
| POST /v1/auth/token | deviceId/deviceKey，随机口令摘要比对，签发5分钟HS256 JWT |
| GET /v1/me | 服务端信用、角色、发布门槛和认领限制 |
| POST /v1/items | UUID幂等发布、图片和时间校验、信用门槛 |
| GET /v1/sync | cursor/limit，变化分页和物品快照 |
| GET /v1/items | kind/category/mine/page/pageSize组合查询 |
| GET /v1/candidates/{lostId} | 本人或管理员可查；五项因子和策略 |
| POST /v1/matches、/v1/claims | 建对或加入串行队列 |
| GET /v1/matches、/v1/matches/{id} | 相关本人/发布者/管理员可查；完成记录可供第三方申诉，凭证仍脱敏 |
| POST /v1/claims/{id}/answer | 仅申请本人、当前核验行可答 |
| POST /v1/claims/{id}/review | 发布者/管理员审核材料与评分 |
| POST /v1/matches/{id}/complete | 全部核验结束后，发布者/管理员确认 |
| POST /v1/matches/{id}/appeals | 高于原凭证的证据；第三方失主 |
| GET /v1/appeals | 本人、对应发布者或管理员 |
| POST /v1/appeals/{id}/decision | 发布者/管理员裁定 |
| GET /v1/notifications | 当前用户通知 |
| GET /v1/admin | SQL平台总数、分类聚合、违规名单和账本 |
| POST /v1/admin/policy、/violations | 管理员配置完整策略、登记人工违规 |

未登录401、越权403、非法流转/重复状态409、字段或证据错误422、超大请求413，统一返回 `error.code/message`。DTO禁止额外字段；JWT验证算法、受众、签发者、期限并再次校对数据库角色。非本人不能读取完整OCR；校园卡/证件图片与详细描述仅本人和管理员可见；标准答案永不下发。调试账户、口令、令牌、真实证据和数据库不公开。
